What I Built and What It Proves

I built an active-active, dual-region distributed object storage platform running entirely on a single developer workstation without relying on Kubernetes or heavy third-party Python packages. The architecture combines containerized MinIO object storage across isolated Docker bridge networks, an active Layer-7 reverse proxy gateway (HAProxy 3.4.7), an autonomous disaster recovery controller implemented as a 5-state deterministic finite state machine, a pull-based GitOps reconciler with automated rollback capabilities, and programmatic network degradation injection via Toxiproxy.

The system demonstrates that enterprise-grade disaster recovery, zero-data-loss failover under crash conditions, and continuous deployment safety gates can be modeled deterministically, inspected at the raw socket and HTTP layer, and evaluated objectively on modest commodity hardware.

Headline Empirical Results in 5 Lines

1. High Availability Failover: Active health checking and Layer-7 redispatch achieve an RTO of 3448 ms (including a 3-second anti-flapping grace window) with zero dropped client writes.
2. Zero Data Loss Under Crash: Measured RPO is exactly 0 missing objects across sequential burst writes during both graceful stop and abrupt SIGKILL crashes.
3. Fast Cryptographic Failback: The metadata inventory gate matches 143+ objects in 1.2 seconds (a 123x speedup over sequential downloads), preventing premature un-fencing.
4. Autonomous GitOps Self-Healing: Broken infrastructure changes trigger automated post-apply health gate failure and stack rollback to last_good in 19.0 seconds.
5. Cryptographic Parity Audit: Byte-for-byte SHA-256 payload audit confirms 153 of 153 objects identical across both region volumes with zero silent data corruption (bit rot).

3. Architectural Design & Topology

Component Architecture

The platform models two geographically distinct availability zones on a single host kernel. Cross-region communication is constrained to a single bridge transit network, providing a programmatic choke point for network fault injection.

Terminal output rendered from docker-compose.yml & docs/03-architecture.md, 10 November 2026

Data Flow for a Normal S3 Write Operation

  1. Client Request: An S3 client crafts an HTTP PUT request with AWS SigV4 authorization headers targeting HAProxy on http://127.0.0.1:8080/demo/object.txt.
  2. Ingress Evaluation: HAProxy checks backend status. Because minio-a is reporting healthy (HTTP 200 on /minio/health/live), HAProxy forwards the stream directly to minio-a:9000.
  3. Persistence & Header Stamp: minio-a commits the payload to the local named volume minio_a_data and returns HTTP 200. HAProxy injects X-Backend-Server: minio-a into the response to client.
  4. Asynchronous Cross-Region Sync: MinIO's internal site replication engine queues the mutation in its replication log. The worker transmits the payload across setu_global directly to Region B (or via Toxiproxy port 9002 during chaos runs). minio-b commits the object to minio_b_data with identical ETag and metadata.

The Complete Narrated Failure Story (End-to-End Self-Healing)

The sequence below narrates the exact chain of events executed during the automated demonstration (make demo), illustrating how the platform detects failure, protects data integrity, and restores service:

Terminal output rendered from demo/demo-run.log, 10 November 2026

Step 1: Disaster Strikes (Region A Dies)

Disaster is injected by abruptly stopping Region A (docker stop setu-multiregion-minio-a-1). Region A's container stops acknowledging TCP connections.

Step 2: Layer-7 Gateway Redispatch

An in-flight client write arriving at HAProxy immediately encounters a closed socket. Because HAProxy is configured with option redispatch and active health checking, it instantly routes the request to the standby server (Region B) on port 9200. The client write succeeds without returning HTTP 502/503.

Step 3: DR Controller Detects Failure & Fences Primary

The DR controller daemon (controller/dr_controller.py) probes Region A's health endpoint every second. Upon receiving a connection failure, it transitions from HEALTHY to DEGRADED. It initiates a 3-second grace window to suppress false alarms from transient network spikes. When Region A remains unreachable after 3 seconds, the controller transitions to FAILOVER and performs administrative ingress fencing: set server minio_api/minio-a state maint. This locks Region A into maintenance mode. The controller issues a write probe to Region B, verifying that the failover path is fully functional, and records the empirical RTO of 3448 ms (or 4011 ms in demo-run.log).

Terminal output rendered from demo/demo-run.log, 10 November 2026

Step 4: Cryptographic Verification & Safe Failback

Region A restarts into quarantine. The DR controller transitions to RECOVERING and holds Region A fenced in MAINT. While MinIO resyncs, compare_sites reports match: false. Once parity is confirmed (match: true), the controller transitions to FAILBACK, issues set server minio_api/minio-a state ready, and returns to HEALTHY.

  1. Continuous Polling: The reconciler monitors the target deployment branch for new commits at a configurable interval (default 3 seconds).

6. Implementation Choices & Design Decisions

Technology Stack Rationale

  • Docker Compose over Kubernetes: Running Kubernetes locally requires 2–4 GB just for the control plane and introduces non-deterministic scheduling. Docker Compose executes natively with minimal memory footprint (~1.2 GB total), keeping networking visible and student-explainable.
  • Chainguard MinIO Image: The official MinIO Docker image was withdrawn from Docker Hub in 2024. We pinned the free, verified Chainguard build (cgr.dev/chainguard/minio by digest sha256:3c60a2a8...).
  • HAProxy over Nginx: Nginx fails to start or reload when an upstream host is down (host not found in upstream "minio-a"). HAProxy resolves hostnames dynamically, supports active health checking, and exposes a runtime UNIX/TCP admin socket for instantaneous zero-reload server fencing.
  • Python Standard Library: The entire controller, proof module, AWS SigV4 signer, and chaos suite are implemented using urllib, socket, hashlib, and hmac. Zero third-party packages (no boto3, botocore, or requests).
  • Toxiproxy over tc netem: Host Traffic Control requires CAP_NET_ADMIN root capabilities, which failed inside unprivileged WSL2. Toxiproxy operates entirely in user-space, providing programmatic REST-controlled WAN simulation.

8. Real Troubleshooting & Field Issues Encountered

During the development of Milestones M0 through M6, several subtle real-world failure modes were encountered and resolved:

Issue 1: Unprivileged tc Network Emulation Failed (Operation not permitted)

  • Symptom: Executing tc qdisc add dev eth0 root netem delay 50ms on the host returned RTNETLINK answers: Operation not permitted.
  • Root Cause: Linux kernel network namespace manipulation requires the CAP_NET_ADMIN capability. Non-root users inside WSL2 or standard containers cannot modify host traffic control queues.
  • Resolution: Deployed Toxiproxy v2.9.0 on the transit bridge. Toxiproxy operates entirely in user-space as a TCP socket proxy, manipulating streams via standard socket I/O without requiring root permissions.

Issue 2: Stale Bind-Mount Cache After Multi-Project Execution

  • Symptom: After running tests on a throwaway project, restarting the main stack caused HAProxy to fail to boot, complaining of missing socket paths.
  • Root Cause: Docker Desktop on WSL2 caches bind-mount inode mappings when containers are recreated across differing compose project names without purging container metadata.
  • Resolution: Use docker compose up -d --force-recreate when switching between project configurations to ensure fresh inode binding.

Issue 3: Nginx Upstream Name Resolution Failure During Backend Outage

  • Symptom: In Milestone M1, when Region A was stopped and Nginx was restarted, Nginx crashed with host not found in upstream "minio-a:9000", causing total ingress failure.
  • Root Cause: Nginx resolves upstream DNS at configuration parse time by default. If a backend container is stopped during startup, Nginx halts entirely.
  • Resolution: Replaced Nginx with HAProxy 3.4.7, which performs dynamic runtime DNS resolution and active Layer-7 health probing without crashing.

Issue 4: Gray Failure Bimodal RTO During docker pause

  • Symptom: In Experiment E2, RTO measurements clustered bimodally around either ~3.6s or ~7.2s.
  • Root Cause: docker pause freezes container execution without closing TCP sockets or sending TCP RST packets. Client worker threads with a 2.0-second timeout were expiring before HAProxy's 2-second connection timeout and redispatch completed.
  • Resolution: Tuned client request timeout to 3.5 seconds in chaos/experiments/e2_pause.py, allowing HAProxy's connect timeout and Layer-7 redispatch to complete gracefully.

12. Mandatory Scope & System Limitations

To maintain rigorous engineering honesty, the following constraints and physical boundaries of this platform are explicitly documented:

1. Eventual Consistency & Last-Write-Wins (LWW)

MinIO site replication is an active-active, eventually consistent distributed storage engine. In scenarios where an un-fenced network partition occurs and concurrent dual-primary writes are issued to identical object keys, MinIO resolves the conflict strictly by object timestamp (Last-Write-Wins). The older version is silently overwritten. Application-level semantic conflict merging is not supported.

2. RPO Measurement Scope & Disk-Loss Boundary

The measured RPO of 0 missing objects was empirically validated under workloads of approximately 35–42 writes/sec with small objects (4 KB – 20 KB) and with surviving disk volumes. This demonstrates replication throughput and socket reliability under test conditions, not a mathematical zero-data-loss guarantee. Physical storage destruction or sudden disk wipe (catastrophic disk destruction) was not tested.

3. RTO Includes Client Timeouts

During gray failures (such as docker pause in Experiment E2), RTO measurements include the client HTTP request timeout (3.5 seconds) in addition to HAProxy's 2-second connection timeout and redispatch window, resulting in measured RTO clustering around ~7.2 seconds.

4. Fast Failback Gate vs. Deep Cryptographic Audit

The automated failback gate (compare_sites in routine operation) evaluates object listings, sizes, and ETags only (sha256_checked: 0) to achieve sub-2-second failback evaluation (1.2s across 140+ objects). Full cryptographic payload streaming and SHA-256 digest computation across every stored object is performed separately via make audit / --deep (sha256_checked: 153).

5. Experiment E3 Run-to-Run Noise

In Experiment E3, measured replication lag under combined latency + bandwidth (2.21s) was lower than the latency-only scenario (3.05s). These differences were within run-to-run timing noise, and the specific underlying cause was not investigated. No trend or causal relationship is claimed.

6. Asymmetric One-Way Partition (E4 Toxiproxy Placement)

Toxiproxy sits specifically on the site-a -> site-b replication path (port 9002). In Experiment E4, timeout toxics severed traffic from site-a to site-b only. site-b's replication endpoint to site-a remained direct (http://minio-a:9000), meaning writes to site-b continued to reach site-a during the cut. This was a one-way (asymmetric) partition, not a complete bidirectional severance.

7. Single-Machine Simulation

Both "regions" execute as Docker containers on a single host Linux kernel. Inter-region WAN characteristics (propagation delay, packet loss, bandwidth caps) were simulated programmatically via Toxiproxy rather than traversing actual cross-continental fiber.

13. Engineering Challenges & What I Learned

Real Bugs Found and Corrected

  • First-Run Replication Bootstrap Timing: In Milestone M0, initial site replication configuration failed intermittently because minio-a attempted to join minio-b before MinIO's internal server pool was fully initialized. Fixed by implementing an active polling readiness loop that verifies HTTP 200 on both backends before issuing mc admin replicate add.
  • Throwaway Test Project-Name Collisions: When testing isolated volume lifecycle scripts, running docker compose without explicit project scoping reused the default project network and named volumes. Resolved by enforcing strict COMPOSE_PROJECT_NAME=setu-fresh-test and isolated volume naming.
  • Demo Pipeline Exit Code Masking: When piping terminal output through tee in scripts/demo.sh, bash masked non-zero exit codes from failed sub-steps. Fixed by capturing ${PIPESTATUS[0]} and asserting positive exit status on every critical gate.
  • Gray Failure Client Socket Deadlock: Paused containers do not emit TCP RST packets. Client workers with short timeouts deadlocked waiting on stale sockets. Resolved by configuring explicit 3.5s client timeouts and tuning HAProxy connect timeouts.
  • Correction of Overstated Early Metrics: In exploratory chaos runs, Experiment E2's hypothesis claimed pause RTO would exceed kill RTO, but measured values varied. Rather than forcing hardcoded pass criteria, the evaluation harness was refactored so that every assertion evaluates real, explicit clauses that can fail, ensuring honest scientific reporting.

Core Systems Engineering Takeaways

  1. Crash vs. Gray Failure Semantics: A hard process termination (SIGKILL) is clean from a networking standpoint because the operating system kernel immediately tears down open file descriptors and emits TCP RST packets. A gray failure (socket freeze / process freeze) is far more hazardous in distributed systems because sockets remain in ESTABLISHED state, forcing reliance on application and proxy connect timeouts.
  2. Ingress Fencing is Essential: Restoring a recovered primary without administrative ingress fencing creates severe split-brain hazards. Fencing primary in HAProxy (MAINT) until cryptographic parity is proven is the only safe method to prevent silent data overwrite.
  3. Targeted GitOps Re-creation: In infrastructure managing persistent state, blanket --force-recreate must never be used. Computing diffs to recreate only modified stateless containers (e.g. gateway) prevents unnecessary storage outages.
  4. User-Space Fault Injection: Programmatic TCP proxying (via Toxiproxy) provides far greater portability and safety than host kernel manipulation (tc netem), avoiding root requirements and privilege leaks.

Technical Glossary

  • RTO (Recovery Time Objective): The elapsed duration between primary failure detection and the first successful write acknowledged on the standby region.
  • RPO (Recovery Point Objective): The quantity of data lost during disaster, measured here as acknowledged client writes missing from the backup region.
  • Failback: The controlled process of restoring primary traffic to Region A after resynchronization is mathematically confirmed.
  • Administrative Fencing: Forcibly locking a failed or recovering node into MAINT state on HAProxy's admin socket to prevent split-brain dual-primary writing.
  • Site Replication: MinIO's active-active bucket and object synchronization mechanism operating over S3 HTTP APIs.
  • GitOps Continuous Delivery: Declarative infrastructure deployment where git commits drive container convergence with automated pre-flight checks and rollback.
  • Chaos Engineering: The discipline of experimenting on a distributed system to build confidence in its capability to withstand turbulent conditions.
